# Getting started

🇬🇧 English · 🇮🇹 [Italiano](../it/getting-started.md) · ⬅️ [Index](index.md)

## Requirements

| Item | Notes |
|---|---|
| LLM API key | [OpenRouter](https://openrouter.ai/) (default) or any OpenAI-compatible endpoint (`OPENAI_API_KEY` + `OPENROUTER_BASE_URL`) |
| At least one channel | Telegram bot token (from [@BotFather](https://t.me/BotFather)) and/or an API token |
| Docker + Compose | Recommended way to run PicoBot |
| [uv](https://docs.astral.sh/uv/) | Needed on the host for the skills admin CLI, local runs and tests |

> [!NOTE]
> The CLI channel alone is not enough for `picobot serve`: it needs Telegram or the API. The CLI is started
> separately with `picobot cli`.

## 1. Configure

```bash
git clone https://github.com/jumping2000/picobot.git && cd picobot
cp .env.example .env
```

Edit `.env` and set at least:

```dotenv
OPENROUTER_API_KEY=sk-or-...
LLM_MODEL_ID=openai/gpt-4o-mini          # cheap: router, SimpleTeam, summaries
LLM_STRONG_MODEL_ID=openai/gpt-4o        # strong: ComplexTeam only (empty = same as LLM_MODEL_ID)

# Telegram (optional)
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_ALLOWED_USER_IDS=123456789      # your numeric Telegram ID; comma-separated

# REST API (optional): "token:user_id", comma-separated
API_TOKENS=<long-random-token>:123456789
```

> [!TIP]
> Generate a token with `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
> Use your Telegram ID as the API `user_id` (and as `CLI_USER_ID`) to **share memory and profile across channels**.

All options are described in [Configuration](configuration.md).

## 2. Prepare the folders

```bash
mkdir -p data workspace skills && sudo chown -R 1000 data workspace
```

The container runs as user `picobot` (UID 1000), which must be able to write to `data/` and `workspace/`.

| Host folder | Container | Mode | Contents |
|---|---|---|---|
| `./data` | `/app/data` | rw | SQLite DB, Telegram state, outbox, inbox |
| `./workspace` | `/app/workspace` | rw | Scripts and files generated by the agents |
| `./config` | `/app/config` | ro | `mcp_config.json` |
| `./skills` | `/app/skills` | ro | Installed skills (hot reload) |
| `./certs` | `/app/certs` | ro | Optional TLS certificates (commented out in the compose file) |

## 3. (Optional) Install skills

Skills enable Office documents. For example, with the `docx`, `pptx` and `xlsx` skills on disk:

```bash
uv run picobot skills add /path/to/skills/docx
uv run picobot skills add /path/to/skills/pptx
uv run picobot skills add /path/to/skills/xlsx
```

See [Skills](skills.md).

## 4. Start

```bash
docker compose up -d --build
docker compose logs -f picobot      # expect "PicoBot pronto (modello=..., strong=..., mcp=N)."
```

`picobot serve` (the container command) starts Telegram, the API and the scheduler in a single process.
Flags: `--no-telegram`, `--no-api`.

## 5. Try it

**Telegram**: send `/help`, then for example "AAPL quote" or a PDF without caption (it gets summarized).

**CLI**:

```bash
docker compose exec -it picobot python -m picobot cli
```

**API**:

```bash
curl localhost:8000/health
curl -X POST localhost:8000/v1/chat -H "Authorization: Bearer $TOKEN" \
     -H "content-type: application/json" -d '{"message":"hello"}'
```

Interactive OpenAPI docs: `http://localhost:8000/docs`.

## Running without Docker

```bash
uv sync
export DATA_DIR=./data WORKSPACE_DIR=./workspace SKILLS_DIR=./skills MCP_CONFIG_PATH=./config/mcp_config.json
uv run picobot serve          # or: uv run picobot cli
```

> [!CAUTION]
> Outside Docker there is no container boundary: generated code (after your confirmation) runs with your user's
> permissions and network access. Prefer Docker. Office skills also need Node.js and the packages in `deps/`.

## Updating

```bash
git pull
docker compose build && docker compose up -d
```

Data in `data/` (sessions, memories, schedules) is preserved.
